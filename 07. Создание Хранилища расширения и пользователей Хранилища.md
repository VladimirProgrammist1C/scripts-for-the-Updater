Автоматизация создания Хранилища 1С для расширения конфигурации 1С и трех пользователей Хранилища: администратора и двух разработчиков с ограниченными правами доступа.

## Листинг скрипта
```@echo off

rem Параметры хранилища и пользователей
set REPO_PATH=D:\Repo1C\ARS_ext
set ADMIN_USER=ARS_ext_admin
set DEV_USER1=ARS_ext_dev01
set DEV_USER2=ARS_ext_dev02

rem Создание хранилища и администратора
echo [1/3] Создаём хранилище и администратора...
%conf1c% /ConfigurationRepositoryF"%REPO_PATH%" /ConfigurationRepositoryN"%ADMIN_USER%" /ConfigurationRepositoryP"123" /ConfigurationRepositoryCreate -AllowConfigurationChanges -ChangesAllowedRule ObjectIsEditableSupportEnabled -ChangesNotRecommendedRule ObjectNotEditable -Extension "АктуализацияСотрудниковДляРассылкиЛистковПоПроизводственномуКалендарю"
if errorlevel 1 (
    echo Ошибка создания хранилища
    exit /b 1
)
echo Хранилище и администратор (%ADMIN_USER%) созданы.


rem Добавление первого разработчика
echo [2/3] Добавляем разработчика 1 (%DEV_USER1%)...
%conf1c% /ConfigurationRepositoryF"%REPO_PATH%" /ConfigurationRepositoryN"%ADMIN_USER%" /ConfigurationRepositoryP"123" /ConfigurationRepositoryAddUser -User "%DEV_USER1%" -Pwd "" -Rights "LockObjects" -Extension "АктуализацияСотрудниковДляРассылкиЛистковПоПроизводственномуКалендарю"
if errorlevel 1 (
    echo Ошибка добавления пользователя %DEV_USER1%
    exit /b 1
)
echo Разработчик %DEV_USER1% добавлен.


rem Добавление второго разработчика
echo [3/3] Добавляем разработчика 2 (%DEV_USER2%)...
%conf1c% /ConfigurationRepositoryF"%REPO_PATH%" /ConfigurationRepositoryN"%ADMIN_USER%" /ConfigurationRepositoryP"123" /ConfigurationRepositoryAddUser -User "%DEV_USER2%" -Pwd "" -Rights "LockObjects" -Extension "АктуализацияСотрудниковДляРассылкиЛистковПоПроизводственномуКалендарю"
if errorlevel 1 (
    echo Ошибка добавления пользователя %DEV_USER2%
    exit /b 1
)
echo Разработчик %DEV_USER2% добавлен.


echo Всё выполнено успешно!
exit /b 0
```

### Пояснения:
* переменные ```REPO_PATH```, ```ADMIN_USER```, ```ARS_ext_dev01```, и ```ARS_ext_dev02``` объявлены заранее и означают "путь к Хранилищу", логин пользователя-администратора Хранилища, логин первого разработчика и логин второго разработчика соответственно.
* ```ConfigurationRepositoryF``` - например, ```D:\Repo1C\zup31\zup_dev_storage```
* ```ConfigurationRepositoryN``` - логин пользователя-администратора хранилища, например, ```Repo_Admin```
* ```ConfigurationRepositoryP``` - пароль пользователя-администратора хранилища, например, ```123qwerty456```
* ```ConfigurationRepositoryAddUser``` - команда создания пользователя хранилища конфигурации. Пользователь, от имени которого выполняется подключение к хранилищу, должен обладать административными правами. Если пользователь с указанным именем существует, то пользователь добавлен не будет. Допустимо использовать следующие параметры:
    * ```-User``` - имя создаваемого пользователя, например, ```Prog_01```
    * ```Pwd``` - пароль создаваемого пользователя, например, ```123qwerty456```
    * ```-Rights``` - Права пользователя. Возможные значения:
        * ```ReadOnly``` - право на просмотр,
        * ```LockObjects``` - право на захват объектов,
        * ```ManageConfigurationVersions``` - право на изменение состава версий
        * ```Administration``` - право на административные функции.
    * ```-RestoreDeletedUser``` - если обнаружен удаленный пользователь с таким же именем, он будет восстановлен.
    * ```-Extension <Имя расширения>``` - позволяет указать имя расширения, с хранилищем которого будет выполняться команда. Если параметр не указан, операция будет выполняться с хранилищем основной конфигурации.

## Требования:
* Конфигуратор должен быть открыт от имени пользователя с административными правами
* В конфигуратор добавлять расширение, устанавливать ему имя, префикс и атрибуты (вроде безопасного запуска и других) придется вручную, т.к. не существует команды пакетного режима для создания расширения из командной строки. Во всяком случае, мне такой команды найти не удалось.
* У пользователя, под которым запускается Обновлятор, должен быть доступ к каталогу Хранилища на чтение, создание и редактирование.

## Автоматизация выполнения скрипта
Для автоматизации выполнения скрипта нужно сохранить его текст в Обновляторе, создать
регламентное задание с типом операции ```ЗАПУСК СКРИПТА```, указать файл скрипта и сохранить в планировщике Windows.
Расписание устанавливать не обязательно, - операция одноразовая и, вероятно, ее повторный запуск не будет нужен.
